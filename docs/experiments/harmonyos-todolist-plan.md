# 鸿蒙 TodoList 插件真实实验

验证 VeriKit 在 OpenClaw 2026.7.1-2 的真实模型会话中，能否完成选 Kit、读取文档、生成鸿蒙应用的流程，并正确处理冲突、关闭设置和路由故障。插件正常运行与应用可运行分别验收，任何失败均保留原始证据。

## 应用范围

单页面 ArkUI TodoList，包含新增、完成与恢复、删除、全部与未完成与已完成筛选、数量统计。空白标题拒绝，标题最长 80 个字符，支持中文和重复标题。通过 ArkData Preferences 保存，应用重新启动后保留待办和完成状态。保存失败应显示错误，不显示保存成功。

采用独立 bundleName，不增加通知、网络、登录或云同步。后续“提醒通知”仅用于检验路由冲突，不并入基础应用。

## 隔离与证据

- 使用独立 OpenClaw 配置、状态、端口、会话及工作区，只加载 VeriKit 与实验观察插件。
- 模型使用现有配置中选定的服务；密钥只存在进程环境，配置使用变量引用，证据脱敏。
- 模型仅可用工作区内的 read、write、edit 和按场景授权的 verikit_route，不授予 Shell 工具。
- 观察插件记录实际模型输入中的路由块、工具顺序与路径、模型输出和运行结束；不改写 VeriKit 的判断或模型响应。
- 用户选择由实验程序按预设脚本提交，标记为实验用户输入，不冒充人工选择。
- SDK 构建、冻结的业务验收和模拟器操作独立执行。构建成功不等同于设备验收通过。
- runtime-corrector-toy、现有鸿蒙项目、日常 OpenClaw 配置和已有模拟器数据不修改。

## 场景与判定

| 场景 | 操作 | 通过条件 |
| --- | --- | --- |
| 首轮路由与选择 | 提交本地持久化 Todo 需求 | 模型实际收到 routing；展示 Kit 选择，确认前不写应用代码 |
| 选择后开发 | 实验用户选择 local-persistence | 不重复等待选择；先 read 选中 Kit 及参考文档，再 write/edit SDK 代码 |
| 手动路由 | 要求调用 verikit_route | 真实工具调用返回 101 条目录基数、配方和存在的参考路径 |
| 冲突 | 使用预先确认可触发冲突的通知需求 | routing.status 为 conflict；模型询问，不直接写代码 |
| 无关问题 | 独立会话提问普通常识 | 无路由块，无文件写入 |
| 提示注入关闭 | 关闭宿主 allowPromptInjection 后冷启动 | 实际模型输入无路由块，插件手动工具仍可按权限使用 |
| 工具拒绝 | 移除 verikit_route 授权后冷启动 | 实际模型工具表不含该工具 |
| 编辑日志 | 无 Kit 提及的新会话直接写 SDK .ets | 写入成功且 gate.log 增加；monitorEdits=false 时不增加 |
| 路由故障 | 仅破坏实验插件副本中的 CLI | 自动路由静默通过，手动工具返回错误，宿主仍能完成普通操作 |
| 路由超时 | 仅将实验副本 CLI 替换为持续等待进程 | 约 15 秒终止路由，宿主继续执行；结束后恢复原文件并核对哈希 |
| 业务逻辑 | 运行冻结的独立验收 | 新增、校验、切换、删除、筛选、序列化往返均正确 |
| 鸿蒙构建 | 使用实际 SDK 构建 debug HAP | 编译与 ArkTS 检查通过，HAP 含实际字节码 |
| 设备验证 | 使用独立模拟器数据目录 | 安装启动成功；新增、切换、筛选、删除和进程重启持久化逐项验证 |

## 执行与归档

先完成主应用真实会话和业务编译，再运行故障与开关对照，最后归档应用代码、各场景结果及脱敏证据索引。场景无法执行时记录原因和已完成的层级，不把接口测试写成设备验收成功。运行脚本位于 scripts/experiments，原始结果保存在 experiments/runs 下。
